01제안 목적

사업의 확장과 성장을 위한 의사결정을,
목표 › 전략 › 실행 › 점검의 프로세스로
일할 수 있게 만듭니다.

성장하는 회사의 의사결정은 한 번의 감이 아니라 반복되는 사이클에서 나옵니다. 숫자로 목표를 세우고, 그 목표를 이룰 전략을 정하고, 실행하고, 결과를 점검해 다음 목표에 반영하는 것. 이 사이클이 빠르게, 정확하게 돌수록 사업은 더 크게 확장됩니다.

이 사이클이 돌아가려면 모두가 같은 숫자를 같은 기준으로 봐야 합니다. 지금 체인저스 캠퍼스는 강의 매출 데이터가 사이트, 외부 매체, 수기 입력 세 곳에 나뉘어 있어 사이클의 마지막인 점검에서 막힙니다. 점검이 늦어지면 다음 목표와 전략도 숫자 대신 감으로 정하게 되고, 사이클이 끊깁니다.

이번 매출 대시보드는 보기 좋은 화면이 목적이 아닙니다. 체인저스 캠퍼스가 단계마다 던지는 질문에 숫자로 답해, 이 사이클을 매주·매월 반복할 수 있게 만드는 도구입니다.

단계이 단계에서 던지는 질문대시보드가 주는 답
목표이번 달·분기에 어떤 강의로, 얼마를 만들 것인가강의·기수별 목표 매출과 현재 진행률
전략어떤 강의·강사·채널에 자원을 더 쓸 것인가강의·강사·채널별 매출, 광고 효율, 공헌이익 비교
실행계획대로 돌아가고 있는가, 지금 손봐야 할 곳은 어디인가매출·광고비·전환 현황과 목표 대비 차이
점검무엇이 효과가 있었고, 다음에는 무엇을 바꿀 것인가목표 달성률, 병목 구간, 기간·기수별 비교

사이트가 구축된 지 얼마 되지 않은 지금이 이 구조를 잡기에 가장 좋은 시점입니다. 데이터 구조를 바로잡는 비용이 가장 낮고, 내부 개발팀이 있어 완성된 대시보드를 이어받아 계속 넓혀 갈 수 있습니다.

경영진은 숫자로 목표와 전략을 정하고, 실무자는 같은 숫자로 실행을 관리하고, 매주 결과를 점검해 다음 결정을 내리는 팀. 이번 프로젝트가 끝났을 때 체인저스 캠퍼스에 남아 있어야 할 모습입니다.

02현황 진단과 해결 과제

조각난 자료를 넘어,
의사결정에 필요한 정보가 담긴
대시보드가 없는 게 문제입니다.

사전 미팅에서 들은 체인저스 캠퍼스의 상황을 정리했습니다. 화면부터 만들면 같은 문제가 화면 안으로 옮겨질 뿐입니다. 그래서 각 현상 뒤에 있는 원인을 짚고, 이번 프로젝트에서 무엇을 정할지 연결했습니다.

지금의 현상그래서 생기는 문제이번에 정할 것
사이트 구축 초기데이터가 쌓이는 방식이 아직 굳지 않아, 나중에 바꾸려면 비용이 커진다지금 시점에 맞는 데이터베이스 구조
있는 데이터·없는 데이터 혼재광고비·외부 결제·강사 정산 같은 숫자가 빠져 매출의 일부만 보인다데이터 소스 지도와 연결 방식
사람이 수기로 입력누락·오타·파일 버전 차이로 숫자가 어긋나고, 누가 언제 고쳤는지 모른다입력 양식·담당자·잠금 규칙
데이터 미정리같은 "매출"도 보는 사람마다 기준이 달라 회의가 숫자 맞추기로 흘러간다지표 사전(계산식·집계 시점·출처)
전체 조망 부재잘되는 강의와 새는 곳을 늦게 알아차리고, 판단이 감에 기댄다경영진용 메인 대시보드
외주 개발 경험외주가 끝난 뒤 구조를 아는 사람이 없어 수정과 확장이 막혔다내부 개발팀 인수인계 방식

착수 첫 주에 실제 사이트 데이터, 수기 입력 파일, 외부 매체 계정을 직접 확인하고 이 진단을 확정합니다.

경영진과 운영 담당자가 매주 확인하는 질문을 먼저 모읍니다. 그 질문에 답하는 데 필요한 지표를 정의하고, 답하는 순서대로 화면을 배치합니다.

지표 사전: 같은 단어, 같은 숫자

대시보드에 올라갈 모든 지표의 이름, 계산식, 집계 기준 시점, 데이터 출처를 한 문서로 고정합니다. 아래는 강의 매출 대시보드에서 정의할 지표의 예시이며, 실제 항목은 착수 후 체인저스 캠퍼스와 함께 확정합니다.

지표정할 기준왜 중요한가
총결제액 · 순매출환불 차감 여부, 결제일 기준인지 강의 귀속 월 기준인지가장 자주 쓰이고 가장 자주 어긋나는 숫자
환불 · 환불율부분 환불 처리, 분모 정의강의 품질과 판매 방식의 문제를 먼저 알려준다
광고비 · ROAS강의·캠페인별 광고비 귀속 규칙채널별 예산 판단의 근거
전환율단계별 분모 정의(신청 → 참여 → 결제)어느 구간에서 고객이 새는지 보여준다
강사 정산 · 공헌이익차감할 비용 항목(광고비·정산금·수수료·기타 비용)매출이 아니라 남는 돈으로 판단하게 한다
목표 달성률목표 입력 단위(월·강의·기수)와 판정 시점진행 중인 숫자와 확정된 숫자를 구분한다

05데이터베이스 기획·설계

화면은 바꾸기 쉽지만, 구조는 바꾸기 어렵습니다.
그래서 구조를 먼저 단단하게 잡습니다.

흩어진 데이터가 서로 이어지려면 공통의 연결 고리가 있어야 합니다. 주문과 유입 경로, 광고비와 캠페인, 수기 입력과 강의가 같은 키로 묶이도록 테이블과 관계를 설계합니다.

설계 항목담기는 내용결과물
데이터 소스 정리데이터별 위치, 생성 주체, 갱신 주기, 품질 상태데이터 소스 지도
테이블 구조강사·강의·기수·주문·환불·광고비·비용 등 핵심 테이블과 컬럼ERD와 테이블 명세
연결 규칙매칭 키(연락처·주문번호·UTM 등), 매출 귀속 규칙, 미분류 처리매칭·귀속 규칙 문서
수기 입력 구조입력 항목·양식·담당자, 마감 후 잠금과 수정 이력입력 양식과 운영 규칙

데이터베이스 설계는 체인저스 캠퍼스 개발팀과 함께 검토합니다. 현재 사이트의 데이터베이스와 기술 환경을 존중하고, 이후 개발팀이 직접 확장할 수 있는 구조로 만듭니다.

06데이터 취합 및 연결

의사결정에 필요한 데이터를 3가지 분류로 나누고,
효과적으로 데이터를 수집 및 관리합니다.

강의 매출과 관련된 데이터를 하나씩 꺼내 어디에 있는지 확인하고, 데이터마다 가져오는 방식을 정해 설계한 데이터베이스로 모읍니다. 기존 수기 데이터는 정리 기준에 맞춰 한 번 정돈한 뒤 옮깁니다.

분류예시연결 방식
사이트에 있는 데이터회원, 주문·결제, 환불, 강의·상품, 유입 경로(UTM)사이트 데이터베이스에서 직접 연결 · 자동
사이트 밖에 있는 데이터광고 매체 비용, PG 정산, 외부 판매 채널API 연동 또는 정기 파일 업로드
사람이 만드는 데이터목표치, 강사 정산 비율, 오프라인 매출, 기타 비용입력 양식 · 담당자 지정

연결은 경영 판단에 영향이 큰 데이터부터, 난이도가 낮은 순서로 진행합니다. 이번 범위에서 자동 연결이 어려운 데이터는 입력 양식으로 먼저 받고, 이후 자동화 방법을 정리해 드립니다. 데이터 접근은 읽기 전용 권한을 원칙으로 합니다.

07대시보드 제작

체인저스 캠퍼스의 목표 달성을 위해
매주 현재 상황을 점검할 수 있는
대시보드를 만듭니다.

설계한 화면을 연결된 데이터 위에 실제로 작동하는 대시보드로 제작합니다. 제작 중에는 매주 진행 미팅에서 화면을 직접 열어보고, 보는 사람의 피드백을 바로 반영합니다.

제작 항목내용
메인 대시보드월별 순매출과 목표 대비 달성률, 강의·강사별 성과, 주요 경고 지표
매출 분석 화면기간·강사·강의·채널 조건별 매출 분해, 정렬과 필터
강의 · 기수 상세강의별 매출·환불·광고비·전환·공헌이익
데이터 입력수기 데이터 입력 양식, 마감 후 잠금, 수정 이력
권한과 내보내기관리자·담당자 권한 구분, 필요한 데이터 추출

제작 방식(자사 서버에 배포하는 웹 대시보드 또는 BI 도구 활용)은 착수 첫 주에 내부 개발팀과 함께 결정합니다. 기준은 하나입니다. 프로젝트가 끝난 뒤 내부 개발팀이 직접 고칠 수 있어야 합니다.

사용 테스트경영진·운영 담당자가 실제 업무 흐름대로 화면을 써보고 불편한 점을 모읍니다보완 사항 반영 완료
사용자 온보딩경영진·운영팀 대상으로 화면 보는 법, 데이터 입력 방법, 지표 기준을 교육합니다담당자가 혼자 입력·조회 가능
